# 보안 점검 (2026-11-01, v0.1.10)

세 갈래로 코드를 읽어 점검했다:
1. Electron 창·IPC
2. AI·MCP·명령줄의 파일 접근과 명령 실행
3. 내장 편집기 서버·Windows 연동·의존성·빌드

위협 모델:
- 문서는 믿을 수 없다 (메일·웹에서 받음, AI에게 지시문을 숨길 수 있음).
- 편집기 묶음은 제3자 코드다.
- 같은 PC의 다른 프로세스와 브라우저의 웹사이트는 믿을 수 없다.
- 사용자는 믿는다.

## 남겨 둔 것 (까닭)

- **코드 서명·asar 무결성**: 인증서가 필요하다. 서명 전까지는 같은 사용자 권한의 악성코드가 설치 폴더의 JS를 고칠 수 있다.
- **한컴 보안 모듈의 SHA-256·서명 확인**: 모듈을 받아 봐야 값을 알 수 있다. 사용자가 받지 않기로 했으므로 커밋 고정까지만 했다.
- **`enableDeprecatedPaste`**: 편집기 메뉴의 붙이기에 필요하다. 편집기 틀이 클립보드를 읽을 수 있으나 네트워크가 막혀 있어 바로 새어 나가지는 않는다.
- **죽은 프록시 포트(127.0.0.1:9)**: 같은 PC의 프로세스가 열 수 있다. 영향이 작아 다음에 고친다.
- **주 창 렌더러가 넘긴 경로를 그대로 쓰는 IPC 일부** (일괄 변환 폴더 등): 렌더러가 뚫려야만 해당한다 (CSP `script-src 'self'`). 다음에 main이 경로를 기억하는 방식으로 바꾼다.
- **큰 파일·압축 폭탄**: 서비스 거부뿐이다. `ooxml-fixups` 한도를 다른 읽기에도 넓히는 것은 다음에 한다.
- **명령줄 `convert`·`text --out`·`image -o`의 덮어쓰기 확인**: 사용자가 직접 치는 명령이라 그대로 둔다.
