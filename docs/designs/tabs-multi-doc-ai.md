## Problem Statement
지금 Office Kit는 문서 하나가 편집 창 하나다. 여러 문서를 열면 창이 따로따로 뜨고, AI 패널은 한 번에 한 문서에만 붙는다. 사용자는 "크롬 창 여러개 띄우듯이" HWP·Word·PPT·Excel·PDF를 한 창의 탭으로 다루고 싶다. 더 중요한 건 탭에 열린 문서끼리 AI로 옮겨 붓는 일(예: Excel 명단으로 HWP 공문 채우기, PDF 내용을 Word 보고서로)이다.

## What Makes This Cool
- 탭은 그릇이고, 핵심은 "열린 탭 여러 개를 AI에 같이 넘기기"다. 다른 오피스 도구에는 이 흐름이 없다.
- AI가 무엇을 고치고 무엇을 읽기만 하는지 화면의 칩으로 보인다 (굵은 칩 = 고칠 문서, 점선 칩 = 읽기 재료).

## Constraints
- Windows 전용 Electron 44 앱, Node 24. 공개 저장소 (toxh13/office-kit), 배포는 GitHub Releases(`v*` 태그 → CI가 NSIS 설치 파일 공개).
- Office 편집기 탭 하나가 약 0.5GB 메모리를 쓴다 (`OFFICE_WINDOWS_NOTICE`).
- 앱 안 AI의 안전장치(`OFFICEKIT_READ_ROOTS/WRITE_ROOTS/EDIT_FILES`, 인터넷 파일 차단, 대화 전 버전 저장)를 약하게 만들지 않는다.
- 사용자에게 보이는 글은 한국어 + 영어·일본어 번역.

## Premises
1. 편집 창은 탭 창(`BaseWindow`) 하나에 문서마다 `WebContentsView` 하나. Ctrl+N으로 탭 창을 더 띄울 수 있음. 탭 끌어 떼어 내기는 다음 버전.
2. 탐색기에서 연 문서는 가장 최근 탭 창의 새 탭으로. 이미 열린 문서면 그 탭으로 이동.
3. 지금의 메인 창(최근 문서·새 문서·도구)은 탭 창의 '홈' 탭이 된다. 별도 창은 없앤다.
4. (2차 의견 뒤 수정) AI가 고칠 문서는 지금 탭 하나뿐이다(v0.2.0). 추가한 탭은 읽기 전용 재료이며 폴더가 아니라 파일 단위로 허용한다. 고칠 문서 여러 개는 v0.2.0에 넣지 않는다(Open Questions).
5. PDF 탭은 보기 전용(내장 PDF 뷰어). AI에는 읽기 재료로만 넘긴다.
6. (Eng Review D2·D13) v0.2.0은 뷰를 내리는 잠재우기를 하지 않는다(v0.2.1, 메모리 측정 후). 다시 켤 때는 활성 탭만 불러오고 나머지는 누를 때 불러온다(지연 로드). 숨은 비문서 뷰(홈·미리보기·AI 패널·탭 줄)만 멈추고, 문서 편집 뷰는 멈추지 않는다.
7. 다시 켜면 탭 목록 복원. 저장 안 한 내용은 기존 자동 저장 사본(`office-drafts`)으로 복구.

## Cross-Model Perspective
독립 Claude 에이전트(대화를 보지 않은 새 맥락)의 의견. 사용자 결정으로 Codex 대신 사용.
- **가장 멋진 버전:** "탭 묶음 + 요청"을 레시피로 저장해, 다음 달에 새 Excel만 바꿔 끼워 같은 작업을 다시 돌리기. AI가 만든 파일은 새 탭으로 열고 탭마다 "AI 전후 비교·되돌리기" 배지.
- **핵심 신호:** 나란히 보기보다 "여러 탭을 AI에 같이"를 먼저 고른 것. 원하는 건 탭이 아니라 문서끼리 옮겨 붓기.
- **참고 오픈소스:** Min 브라우저의 탭 구조(탭 줄, 뷰 생명주기, 포커스·단축키 이중 처리). 직접 만들 부분은 저장 확인 흐름의 탭 단위 이동, 종류별 세션 유지, 탭 재우기, 탐색기 → 탭, 여러 문서 AI 권한.
- **반박 (Critical):** 지금 규칙을 그대로 넓히면 고른 문서들의 폴더 전체가 읽기·쓰기 범위가 되고, 인터넷 PDF 속 지시문이 함께 넘긴 다른 문서를 고치게 만들 수 있다 → 전제 4를 "고칠 문서 1개 + 파일 단위 읽기 재료"로 고침.
- **High:** 홈 화면 렌더러(`src/app/renderer/app.js`, 2781줄)가 전체 창·옆 창 두 모드를 한 인스턴스로 오가므로, 홈 탭과 AI 패널이 동시에 보이려면 먼저 나눠야 한다. 편집 창 생명주기가 BrowserWindow 전용 이벤트(`close`, `closed`)에 묶여 있어 탭 닫기 흐름을 새로 짜야 한다.
- **Medium:** Office 뷰를 내리면 되돌리기 기록·커서가 사라진다 → 전제 6에 반영.

## Approaches Considered
- A. AI 먼저, 탭은 다음 버전 (M · 낮음) — v0.2.0에 탭이 빠져서 사용자가 정한 범위와 다름.
- C. 기존 편집 창 위에 탭 줄 창만 띄워 앞으로 가져오기 (M · 높음) — 창 깜빡임·순서 꼬임, "가짜 탭".

## Recommended Approach
**B. 단계별로 둘 다, 합쳐서 v0.2.0.** 위험한 보안 경계부터 따로 검증하고 그 위에 탭을 올린다.

- **M1. AI 역할 구조 (지금 창 구조에서 먼저 완성·시험)**
  - **읽기 범위(정확히):** ① 고칠 문서의 폴더 전체(지금과 같음. 그림 넣기 등 상대 경로가 여기에 의존), ② 읽기 재료 파일 각각(파일 하나씩, 그 폴더의 다른 파일은 아님), ③ 이 대화에서 AI가 새로 만든 파일(`createdHere`). 쓰기 범위는 고칠 문서 폴더와 고칠 문서·새로 만든 파일만(지금과 같음).
  - **`OFFICEKIT_READ_FILES`를 읽는 곳 전부:** `mustExist`(위 ①②③ 중 하나면 허용), `office_hwpx_batch`(READ_FILES가 있으면 폴더 입력은 ①의 폴더만, 파일 입력은 ①②③만; 모은 파일도 같은 규칙으로 거름), `restricted()`(READ_FILES가 있으면 제한 모드), `guardUnc`(네트워크 경로는 ①의 폴더 안이거나 ②에 정확히 있는 파일만).
  - **저장 안 한 읽기 재료 탭:** 보내기 전에 "‘명단.xlsx’에 저장 안 한 편집이 있어 저장된 내용을 읽습니다 — 저장하고 보내기 / 그대로 보내기 / 취소"를 묻는다(`EDITOR_DIRTY`와 같은 흐름). 시험 포함.
  - **재료가 바뀔 때의 대화:** 보낼 때 읽기 목록을 고정한다. 재료를 더하면 같은 대화를 이어 간다. 인터넷 파일(Zone 3) 재료를 빼면 이어 하기 세션을 버리고 새 대화로 시작한다("자료가 바뀌어 새 대화로 시작합니다" 표시, 화면 기록은 남김). 시험 포함.
  - `aiMcpEnv(docPath)` → `aiMcpEnv({ edit: [path], read: [paths] })`. `READ_ROOTS` 대신 파일 목록(`OFFICEKIT_READ_FILES`)을 넘기고, `src/mcp/server.mjs`의 `mustExist`가 파일 단위 허용 목록을 따르게 한다. `WRITE_ROOTS`는 고칠 문서 폴더만.
  - `sendChat`의 `needDoc()` 하나 → "대화 대상" { edit, read[] }. 대화 전 버전 저장·`EDITOR_DIRTY` 확인·되돌리기는 고칠 문서 기준. 읽기 재료는 바꾸지 않으므로 버전 저장 불필요.
  - 읽기 재료에 인터넷 파일(Zone 3)이 있으면 AI 패널 칩에 "인터넷 파일" 표시. 인터넷 Office 파일은 파일 엔진으로만 읽는다(COM 금지, 지금 `UNTRUSTED` 규칙 그대로).
  - 이어 하기 세션 키는 "고칠 문서 경로"로 유지한다. 예외: 인터넷 파일(Zone 3) 읽기 재료를 빼면 그 키의 세션을 지워(`sessions.delete`) 다음 메시지부터 새 대화로 시작하고, 화면의 대화 기록은 남긴다.
- **M2. 화면 코드 분리** — `src/app/renderer/app.js`를 홈 화면과 AI 패널 두 진입점으로 나누고, main의 `current` 하나를 "탭 창마다 활성 탭"으로 바꿀 준비. 기존 옆 창 모드(`showPanel`/`panelOf`/`leavePanel`)는 이 단계 끝에 제거.
- **M3. 탭 창** — `src/app/tab-window.mjs`(새 파일): `BaseWindow` + 탭 줄 뷰 + 문서 뷰들 + AI 패널 뷰.
  - `editor-window.mjs`의 `entry.win` 의존(`senderEntry`, `ask`, `requestClose`, `updateTitle`, `focus`, `closeAll`, 인쇄 부모 창)을 "탭을 담는 창 + 탭 뷰"로 나눈다. 뷰를 닫을 때 `webContents.close()`를 직접 부른다.
  - 단축키: Ctrl+T(새 탭=홈), Ctrl+W(탭 닫기), Ctrl+Tab/Ctrl+Shift+Tab, Ctrl+1~9, Ctrl+N(새 탭 창). 탭 줄 뷰와 각 문서 뷰의 `before-input-event` 양쪽에서 처리.
  - 닫기: 탭 하나 닫기 = 그 탭만 저장 확인. 창 닫기 = 저장 안 한 탭을 차례로 확인, 하나라도 취소하면 창 유지. 끝내기 취소 시 상태 복원(v0.1.13 버그 13 수정 유지).
  - 탐색기에서 열기(`second-instance`, `openAsDocument`) → 최근 탭 창의 새 탭. 같은 문서면 그 탭으로.
  - **인터넷에서 받은 Office 파일(Zone 3, HWP 제외):** 편집 탭이 아니라 "보기 전용 미리보기 탭"으로 연다(지금 홈 미리보기와 같은 글자/PDF 미리보기, 상단에 "인터넷에서 받은 파일 — 편집하려면 파일 속성에서 차단 해제" 안내). 읽기 재료로는 넘길 수 있고 고칠 문서는 될 수 없다. `UNTRUSTED` 규칙은 바꾸지 않는다.
  - **AI 작업 중 탭 닫기:** 고칠 문서 탭을 닫으면 "AI가 이 문서를 고치는 중입니다 — 멈추고 닫기 / 취소"를 묻고, 멈추기를 고르면 지금의 중단 흐름(숨은 Office 정리 포함)을 탄 뒤 닫는다. 읽기 재료 탭은 그냥 닫히고, 진행 중인 요청에는 영향이 없다(보낼 때 목록 고정).
  - 다시 켜면 탭 목록 복원(`settings`에 창별 탭 경로 목록). 없는 파일은 건너뛰고 알림.
  - PDF 탭: 지금 홈 미리보기에서 쓰는 사본 + 내장 PDF 뷰어를 탭 뷰로.
- **M4. 메모리 (v0.2.0은 지연 로드만, 아래 잠재우기는 v0.2.1)** — 백그라운드 탭은 `setBackgroundThrottling`. 기준은 메모리 측정이 아니라 **불러온 Office 뷰 수**(기본 6): 7번째를 열 때 저장된 Office 탭 중 가장 오래 안 쓴 것부터 뷰를 내린다(점선 탭, 누르면 다시 열림). 내릴 수 있는 탭이 없으면(모두 저장 안 함) 지금의 메모리 안내(`OFFICE_WINDOWS_NOTICE`)를 띄우고 그대로 연다.

Wireframe: projects/toxh13-office-kit/ 아래 sketch 파일 (상태 1: 문서 탭 + AI 패널, 상태 2: 열린 탭 추가 메뉴, 상태 3: 홈 탭). 위 탭 줄 · 왼쪽 문서 · 오른쪽 AI 패널 배치로 사용자 승인.

## Eng Review 결정 (구속력 있음, 2026-11-25 /plan-eng-review)
이 절이 위 본문과 다르면 이 절이 우선한다. 근거와 선택지는 문서 끝 Decision ledger(R1~R14).
- 범위: 탭 창 여러 개(Ctrl+N) 유지(D1). M4 잠재우기는 v0.2.1, v0.2.0은 지연 로드만(D2). 숨은 문서 탭은 멈추지 않음(D13).
- 구조: editor-window.mjs가 문서 상태·WebContentsView·정리를 소유, tab-window.mjs는 문서 상태 없는 얇은 껍데기(attach/detach/dialogParent/setTitle/focusTab)(D3). AI 이벤트는 chatId → 시작한 탭 창의 AI 패널로만, current는 탭 창별.
- 복원: 평소 시작은 자동 복원, 탐색기로 문서를 열며 시작하면 그 문서만 + 홈 탭 '지난 탭 다시 열기'(D4). 탭 창별 목록 1초 디바운스 저장, 끝내기·마지막 창 닫기 순간을 '지난 세션'으로 확정, 탐색기 시작 세션은 지난 세션 칸을 덮지 않음(D9·D11).
- 인터넷 Office 파일: 탐색기 경로도 보기 전용 미리보기 탭(지금은 앱 안 편집기로 열림 → 동작 변경) + 'Windows 프로그램으로 열기' 버튼(D5).
- IPC: src/app/ipc-channels.mjs 채널 → 허용 뷰 종류 표 하나에서 main 검사·preload 노출 생성(D6).
- AI 권한: 고칠 문서 없이 재료만이면 '새 파일 만들기' 모드(기존 파일 덮어쓰기 금지, 출력 폴더 기본=첫 재료 폴더)(D10). 인터넷 재료가 있는 동안 읽기 범위는 고칠 문서 파일 하나 + 재료 파일들(D15). AI가 고치는 중인 문서는 다른 대화의 재료 금지(D14). 저장 안 한 재료 확인은 지연 로드 탭의 자동 저장 사본도 본다. 재료 목록은 메시지마다 데이터 줄로 전달.
- 닫기: 탭·창·끝내기 모두 AI 작업 중이면 '멈추고 닫기 / 취소'(D17). 단축키는 탭 줄·문서·AI 패널·홈 뷰 모두에서 동작.
- 메모리 안내: 불러온 Office 편집 뷰 4개 초과 시 한 번(D12).
- 시험: test/helpers/fake-electron.mjs 공용(D7), 기존 편집 시험 단언 전부 탭 구조로 이전(D8), 실제 Electron 탭 창 스모크 1개 CI 실행(D16).

## Open Questions
- 고칠 문서 여러 개(UI, 쓰기 범위, 문서별 버전·되돌리기, 세션 키)는 v0.2.0 밖. 필요해지면 따로 설계.
- 탭 순서를 끌어서 바꾸기를 v0.2.0에 넣을지 (떼어 내기는 제외 확정).
- 홈 탭을 닫을 수 있게 할지 (기본: 고정, 닫기 없음).
- 잠든 Office 탭을 다시 열 때 자동 저장 사본과 원본이 다르면 어떻게 할지 (M4는 저장된 탭만 재우므로 원칙상 같음).
- AI가 새로 만든 파일을 자동으로 새 탭에 열지, 칩으로 "열기"만 보여 줄지.

## Success Criteria
- 서로 다른 형식 5개(HWP, DOCX, PPTX, XLSX, PDF)를 한 탭 창에서 열고, 탭 전환·닫기·저장 확인이 모두 맞게 동작.
- "Excel 명단 → HWP 공문 채우기" 시나리오가 처음부터 끝까지 동작하고, 그동안 Excel 원본은 바이트 하나 바뀌지 않음(시험으로 확인).
- 읽기 재료의 폴더가 고칠 문서의 폴더와 다를 때, 그 폴더의 다른 파일은 AI가 읽지 못함(시험으로 확인). 같은 폴더면 지금처럼 읽을 수 있음.
- 저장 안 한 읽기 재료 탭, 인터넷 파일 재료 빼기, AI 작업 중 고칠 문서 탭 닫기가 위에 정한 대로 동작(시험으로 확인).
- 앱을 끄고 다시 켜면 탭 목록이 돌아옴. 저장 안 한 편집은 기존 자동 저장 사본으로 복구 안내.
