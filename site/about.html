만든 방법

Office Kit은 개발자 한 명이 AI 코딩 도구와 함께 만든 Windows용 오픈소스 문서 도구입니다. 무엇으로 만들었고, 어떻게 확인하는지 정리했습니다.

무엇으로 만들었나

앱은 여러 오픈소스 부품을 하나로 묶은 구조입니다. 문서를 실제로 읽고 쓰는 일은 각 형식에 맞는 엔진이 맡습니다.

부분쓰는 것하는 일

부품마다 라이선스와 출처는 제3자 고지에 있습니다.

데이터가 가는 곳

  • Office Kit에는 자체 서버가 없고, 사용 기록을 모으지 않습니다. 자동 업데이트도 없습니다.
  • 직접 편집, 개인정보 가리기, PDF 도구는 인터넷 없이 이 PC 안에서만 동작합니다. 편집 창은 앱 밖으로 나가는 요청을 막습니다.
  • AI 대화를 쓸 때만 문서 내용이 내 계정으로 Anthropic(Claude Code) 또는 OpenAI(Codex)에 전송됩니다. Office Kit은 로그인 정보를 다루지 않고, 내 PC에 설치된 공식 프로그램을 고치지 않고 그대로 실행합니다.

AI와 함께 만든 과정

코드, 테스트, 문서는 개발자가 Anthropic의 Claude Code와 함께 작성했습니다. 저장소의 모든 커밋에 Claude가 공동 작성자로 기록되어 있습니다.

  • 개발자가 정한 것: 무엇을 만들지, 설계 방향, 배포와 공개 여부, 라이선스와 약관 판단.
  • AI와 함께 한 것: 코드와 테스트 작성, 버그 찾기, 문서와 이 사이트, 화면 사진 촬영.
  • AI가 쓴 코드도 사람이 쓴 코드와 같은 자동 테스트와 점검을 거쳐야 Release에 들어갑니다.

앱의 AI 대화 기능은 이 개발 과정과 별개입니다. 사용자가 자기 PC에 설치하고 로그인한 AI를 씁니다.

어떻게 확인하나

  • 자동 테스트 약 670개가 GitHub에 올릴 때마다 돕니다. 실패하면 설치 파일을 만들지 않습니다.
  • 보안 점검: 창과 앱 사이 통신, AI와 명령줄의 파일 접근, 편집기 서버를 나눠 코드를 읽고 고쳤습니다 (점검 기록).
  • 공개 전 점검: 비밀값과 개인정보가 저장소에 없는지, 라이선스 의무를 지키는지 확인했습니다.
  • 이 사이트의 화면 사진은 실제 앱에서 가짜 데이터 문서를 열어 찍었습니다.

서명되지 않은 이유

처음 실행할 때 “Windows의 PC 보호” 창이 뜰 수 있습니다. 설치 파일에 코드 서명이 없어서입니다. 코드 서명 인증서는 보통 회사나 유료 구매가 필요하고, 개인 오픈소스 프로젝트는 무료 서명 서비스를 쓰려면 일정한 사용자 수와 인지도가 먼저 있어야 합니다. Office Kit은 아직 그 단계 전이라 당분간 서명 없이 배포합니다.

  • 창이 뜨면 추가 정보를 누르고 실행을 고르면 설치됩니다.
  • 받은 파일이 GitHub Release의 파일과 같은지 PowerShell로 확인할 수 있습니다.
Get-FileHash .\OfficeKit-Setup-0.1.12.exe -Algorithm SHA256
# 결과가 아래와 같아야 합니다 (0.1.12)
# A5F2765F76D6BFC7BA547331E3E5A70A6C376A05E7DC5B1D7768B7D0F1E48B7B

서명 방침과 준비 상황: 코드 서명 정책.

소스와 라이선스

  • 모든 소스는 GitHub 저장소에 있습니다. Release 태그마다 그 판의 소스입니다.
  • Office Kit이 직접 쓴 코드는 MIT입니다. 함께 담긴 문서 편집기가 GNU AGPL 3판이라, 설치된 앱 전체는 AGPL 조건으로 배포합니다.
  • 편집기를 이룬 원본 소스는 커밋 그대로 사본 저장소에도 두었습니다.

Office Kit은 무료 오픈소스이며 아무런 보증이 없습니다. 앱 코드는 MIT이고, 함께 담긴 문서 편집기(ONLYOFFICE Docs 기반 수정판)가 GNU AGPL 3판이라 설치된 앱 전체는 AGPL 조건으로 배포합니다. 자세한 내용은 라이선스 문서에 있습니다.

ONLYOFFICE는 Ascensio System SIA의, Word·Excel·PowerPoint는 Microsoft의, 한컴·한글·HWP는 한글과컴퓨터의 상표입니다. Office Kit은 이들 회사와 관계가 없습니다.
